# Поддержка карты данных

Карта в `DataMap/` предназначена для прямого редактирования командой. Эта папка содержит происхождение первой итерации, исходные профили и средства проверки. Большие источники не копируются в Git.

## Что хранится здесь

- `evidence/`: JSON-профили исследования от 09.09.2026, структуры первых строк исходников, SHA-256, текст ТЗ и адресные проверки.
- `research_scripts/`: три исходных скрипта исследования; пути заменены на аргументы `--source` и `--output`, временные lock-файлы Office исключены из инвентаризации. Исходные файлы читаются без изменений.
- `build_map.py`: сборка первой итерации из сохранённых свидетельств и явно написанных пояснений.
- `validate_map.py`: проверка локальных ссылок, идентификаторов, покрытия и Folder Notes.

Для чтения карты, установки плагина, генерации и проверки достаточно Python 3.11+ без сторонних библиотек. Obsidian требует версию, совместимую с Folder Notes (минимум 1.4.10 по manifest).

## Проверка карты

Из корня репозитория:

```powershell
python tools/datamap/validate_map.py
python -m unittest discover -s tools -p test_setup_vault.py
```

## Повторная генерация

```powershell
python tools/datamap/build_map.py --output ../DataMap-review
```

Генератор откажется перезаписывать существующие заметки. Он не переносит будущие ручные правки команды автоматически. Генерируйте в новый каталог, скопируйте туда `DataMap/Вложения/scheme-*.png`, проверьте его через `validate_map.py --vault ../DataMap-review`, затем просмотрите различия и перенесите нужные изменения. Не заменяйте рабочую карту целиком после ручного редактирования.

Структура и статистика берутся из JSON. Отдельные проблемные случаи и выводы закреплены в тексте генератора для версии исходников, указанной в source_inventory.json. При обновлении данных недостаточно заменить JSON: потребуется пересмотр чисел в пояснениях, открытых вопросов и всех зависимых карточек.

## Повторить исследование исходников

Установить версии из `requirements-research.txt` в отдельное окружение. Указать локальную папку с семью файлами пакета и новый каталог результатов. Обязательный порядок:

```powershell
python -m pip install -r tools/datamap/requirements-research.txt
python tools/datamap/research_scripts/inspect_sources.py --source ../hakathon-data --output ../datamap-audit
python tools/datamap/research_scripts/profile_data.py --source ../hakathon-data --output ../datamap-audit
python tools/datamap/research_scripts/check_findings.py --source ../hakathon-data --output ../datamap-audit
```

Пути в примере заменяются фактическими локальными путями. Исследование читает весь набор и требует памяти для CSV/Excel. Результаты пишутся в `--output`; не указывайте папку исходников. Сверить SHA-256 с `evidence/source_inventory.json`, затем сравнить профили. Исходная статистика без удаления выбросов; лабораторные служебные записи учитываются отдельно от чисел. Исходные скрипты расчёта не обучают модели.

PNG схем получены из трёх страниц `АВТ_схемы.pdf` с Poppler: `pdftoppm -scale-to 2600 -png АВТ_схемы.pdf scheme`. Изображения включены для чтения внутри Obsidian.

## Folder Notes

`../setup_vault.py` устанавливает локально зафиксированный релиз из `../obsidian/folder-notes/`. Версия, ссылки и SHA-256 в `../obsidian/provenance.json`; лицензия upstream рядом с файлами. Установщик не скачивает и не исполняет код плагина, а размещает файлы для Obsidian. Вся живая `.obsidian/` остаётся локальной и игнорируется Git.

При обновлении зафиксированного релиза заменить комплект assets только целиком, сохранить лицензию и обновить provenance. Существующие пользовательские установки bootstrap не обновляет; их можно обновить штатно в Obsidian. Личные настройки не версионируются.
