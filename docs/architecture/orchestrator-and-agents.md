# Оркестратор и агенты

Этот документ описывает, как оркестратор взаимодействует с агентами и как агенты должны отдавать результаты.

## Главный принцип

Оркестратор - это управляющий модуль, а не экспертная модель. Он не должен знать внутренние формулы качества, границы риска оборудования или логику генерации сценариев. Его задача - запускать модули, проверять их структурированные ответы и управлять переходами между слоями.

Каждый агент получает общий `ProcessState` и возвращает свой `AgentResult`.

```text
input: ProcessState
output: AgentResult
```

Пример:

```python
result = quality_agent.run(process_state)
process_state.quality_state = result
```

## Порядок запуска

Рекомендуемый порядок:

```text
1. DQ Checker
2. Quality Agent и Reliability Agent
3. Scenario Optimizer
4. Safety Gate
5. Pareto / Ranking
6. LLM Explainer
```

`DQ Checker` должен идти первым. Если данные плохие, дальнейшие расчёты не имеют смысла или должны выполняться только в режиме отказа от рекомендации.

`Quality Agent` и `Reliability Agent` можно запускать параллельно после DQ, потому что они решают разные задачи:

- Quality Agent оценивает качество продукта;
- Reliability Agent оценивает тяжесть режима.

`Scenario Optimizer` запускается после Quality и Reliability, потому что сценарии должны учитывать текущие риски, запреты и уверенность в данных.

## DQ Checker

### Что приходит

Исходный `ProcessState`:

- синхронизированный срез телеметрии АВТ;
- синхронизированный срез телеметрии 24-2000;
- последний ЛИМС до текущего момента;
- последний ПАК до текущего момента;
- возраст ЛИМС и ПАК;
- список критичных тегов;
- справочник тегов;
- лаговые и rolling-признаки.

### Что происходит

Модуль проверяет:

- наличие критичных тегов;
- пропуски;
- дубли времени;
- свежесть ЛИМС и ПАК;
- аномальные скачки;
- flatline-сигналы;
- расхождение ПАК со свежим ЛИМС;
- возможность продолжать расчёт.

### Инструменты

- набор правил;
- статистические проверки;
- robust z-score;
- IQR/MAD;
- пороги свежести анализов;
- список критичных тегов.

### Что выходит

```json
{
  "data_status": "limited",
  "confidence": 0.72,
  "freshness": {
    "lims_age_hours": 18.5,
    "pak_age_minutes": 10
  },
  "missing_critical_tags": ["T5", "P13"],
  "anomalies": [
    "скачок расхода F9 за последний час"
  ],
  "source_priority_used": {
    "sulfur": "PAK",
    "D15": "LIMS"
  },
  "can_continue": true,
  "can_recommend": true,
  "blocking_reasons": []
}
```

### Как оркестратор использует результат

```text
can_continue = false
  -> остановить расчёты
  -> сформировать отказ: данных недостаточно

can_recommend = false
  -> можно посчитать диагностику
  -> нельзя выдавать управляющую рекомендацию

missing_critical_tags содержит T5
  -> Scenario Optimizer не может предлагать действие по T5
```

## Quality Agent

### Что приходит

`ProcessState` после DQ:

- качество входных данных;
- ЛИМС, ПАК и ВАК;
- телеметрия АВТ и 24-2000;
- лаги и rolling-признаки;
- источник, которому доверяем по каждому показателю.

### Что происходит

Модуль оценивает текущее и прогнозное качество продукта:

- содержание серы;
- плотность `D15`;
- фракционный состав, если хватает данных;
- риск выхода за спецификацию;
- уверенность прогноза.

ЛИМС имеет приоритет над ПАК, ПАК - над ВАК, ВАК - над косвенными КИП-признаками.

### Инструменты

- ВАК-формулы из справочника;
- регрессионная модель;
- ML-модель для временных признаков;
- оценка неопределённости;
- проверка жёсткого предела серы `<= 10 mg/kg`.

### Что выходит

```json
{
  "current_quality": {
    "sulfur_mg_kg": 7.8,
    "d15_kg_m3": 831.2,
    "t95_c": 342.0
  },
  "forecast_quality": {
    "sulfur_mg_kg": 8.6,
    "d15_kg_m3": 832.0,
    "t95_c": 344.5
  },
  "spec_risks": {
    "sulfur_limit_10_mg_kg": "medium",
    "d15": "low"
  },
  "confidence": 0.76,
  "main_drivers": [
    "рост температуры T6",
    "изменение расхода F9",
    "ПАК свежий, ЛИМС устарел"
  ],
  "hard_violations": []
}
```

### Как оркестратор использует результат

```text
sulfur risk = critical
  -> разрешать только консервативные сценарии

hard_violations не пустой
  -> передать в Safety Gate
  -> финальная рекомендация не может ухудшать нарушение

confidence низкая
  -> повышать осторожность Scenario Optimizer
```

## Reliability Agent

### Что приходит

`ProcessState` после DQ:

- режимные параметры АВТ и 24-2000;
- температуры;
- давления;
- перепады;
- расходы;
- изменения за последний час/смену;
- качество входных данных.

### Что происходит

Модуль оценивает тяжесть режима и риск для оборудования или катализатора. Так как в пакете нет прямой разметки отказов, используется прокси-риск.

Примеры факторов:

- температура близка к верхней модельной границе;
- перепад давления вырос;
- расход резко изменился;
- режим находится около исторического экстремума;
- несколько связанных сигналов изменились несогласованно.

### Инструменты

- скоринговая функция;
- набор правил;
- модельные диапазоны;
- robust statistics;
- риск-классы.

### Что выходит

```json
{
  "risk_score": 0.64,
  "risk_class": "elevated",
  "limiting_factors": [
    "температура реактора близка к верхней модельной границе",
    "перепад давления вырос за последние 6 часов"
  ],
  "forbidden_changes": [
    {
      "parameter": "T5",
      "reason": "дальнейшее повышение увеличивает тяжесть режима"
    }
  ],
  "confidence": 0.7
}
```

### Как оркестратор использует результат

```text
forbidden_changes содержит increase T5
  -> Scenario Optimizer не имеет права предлагать повышение T5

risk_class = critical
  -> можно разрешить только сценарии снижения риска

confidence низкая
  -> сценарии должны быть осторожнее или перейти в отказ
```

## Scenario Optimizer

### Что приходит

Обновлённый `ProcessState`:

- вывод DQ Checker;
- вывод Quality Agent;
- вывод Reliability Agent;
- список управляемых параметров;
- модельные диапазоны;
- ограничения качества;
- запреты на изменения.

### Что происходит

Модуль генерирует кандидатные варианты действий. Он не выдаёт финальную рекомендацию и не объясняет её оператору.

### Инструменты

- генератор сценариев;
- grid search;
- эвристики;
- локальная оптимизация;
- forecast-функции для оценки эффекта;
- constraints-aware search.

### Что выходит

```json
{
  "candidate_scenarios": [
    {
      "scenario_id": "S1",
      "changes": [
        {
          "parameter": "T5",
          "current": 365,
          "proposed": 362,
          "unit": "C"
        }
      ],
      "expected_effect": {
        "sulfur_mg_kg": 8.7,
        "reliability_risk_score": 0.58,
        "production_proxy": -0.01,
        "energy_proxy": -0.03
      },
      "confidence": 0.74
    }
  ]
}
```

### Как оркестратор использует результат

Оркестратор не выбирает сценарий сразу. Он передаёт кандидатные сценарии в `Safety Gate`.

## Safety Gate

### Что приходит

Кандидатные сценарии и весь `ProcessState`.

### Что происходит

Модуль проверяет жёсткие ограничения и отбрасывает недопустимые сценарии.

### Инструменты

- deterministic rules;
- проверка hard constraints;
- список причин отсева;
- audit log.

### Что выходит

```json
{
  "accepted_scenarios": ["S1"],
  "rejected_scenarios": [
    {
      "scenario_id": "S2",
      "reason": "forecast_sulfur_mg_kg > 10"
    }
  ],
  "can_issue_recommendation": true
}
```

## Pareto / Ranking

### Что приходит

Только сценарии, прошедшие Safety Gate.

### Что происходит

Модуль выбирает лучшие допустимые сценарии по нескольким критериям:

- качество продукта;
- риск оборудования;
- выпуск;
- энергозатраты;
- уверенность прогноза.

### Инструменты

- Pareto front;
- weighted scoring;
- lexicographic sorting.

### Что выходит

```json
{
  "selected_scenario": "S1",
  "alternatives": ["S4"],
  "selection_reason": "минимальный риск по сере при допустимой тяжести режима"
}
```

## LLM Explainer

### Что приходит

`Recommendation Packet`, а не весь `ProcessState`.

### Что происходит

LLM формулирует понятный оператору текст. Она не пересчитывает показатели и не переигрывает решение.

### Инструменты

- LLM;
- шаблон ответа;
- ограничения на неподтверждённые выводы.

### Что выходит

```text
Рекомендуется сценарий S1: снизить T5 на 3 C.
Вариант выбран, потому что прогноз по сере остаётся ниже 10 мг/кг,
а риск тяжёлого режима снижается. Уверенность средняя: последний ЛИМС
устарел, поэтому расчёт опирается на свежий ПАК и ВАК.
```
