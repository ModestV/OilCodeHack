# Приоритеты данных и связь источников

Архитектура зависит от правильного отношения к источникам данных. В задаче Нефтекод источники не равноправны: у них разная частота, разная надёжность и разная роль в принятии решения.

## Главная иерархия по качеству

```text
ЛИМС -> ПАК -> ВАК -> КИП
```

## ЛИМС

### Роль

ЛИМС - лабораторная информационная система. Это контрольный факт качества.

### Что даёт

- серу;
- плотность `D15`;
- фракционный состав;
- температуру помутнения;
- температуру вспышки;
- другие лабораторные показатели.

### Особенности

- измерения редкие;
- измерения асинхронные;
- разные показатели могут иметь разный возраст;
- ЛИМС запаздывает относительно процесса;
- при конфликте со свежим ПАК или ВАК ЛИМС имеет приоритет как контрольный факт.

## ПАК

### Роль

ПАК - поточный аналитический контроль. Он даёт оперативное измерение качества.

### Что даёт

- `24-2000:Mg.Sulfur`;
- `24-2000:D15`.

### Особенности

- чаще ЛИМС;
- ближе к online-контролю;
- может быть недоступен или сбиться;
- не должен автоматически считаться истиной, если есть свежий ЛИМС.

## ВАК

### Роль

ВАК - виртуальный анализатор качества. Это расчёт качества по технологическим параметрам.

### Что даёт

В справочнике есть формулы для расчёта показателей качества по КИП-сигналам:

- `D15`;
- `T50`;
- `T90`;
- `T95`;
- `CloudPoint`;
- `CFPP`;
- другие расчётные показатели.

### Особенности

- это не измерение, а модельная оценка;
- полезен при отсутствии свежего ЛИМС или ПАК;
- может быть baseline для Quality Agent;
- не должен отменять свежий лабораторный факт.

## КИП

### Роль

КИП - технологический контекст: температуры, давления, расходы, уровни.

### Что даёт

- состояние АВТ;
- состояние 24-2000;
- признаки для ВАК;
- признаки для Quality Agent;
- признаки для Reliability Agent;
- признаки для Scenario Optimizer.

### Особенности

КИП сам по себе не является качеством продукта. Он объясняет режим, который влияет на качество и риск оборудования.

## Как источники связываются

Связь выполняется только по времени.

```text
момент t
  -> телеметрия АВТ на t или с лагом
  -> телеметрия 24-2000 на t
  -> последний ЛИМС до t
  -> последний ПАК до t
  -> возраст ЛИМС
  -> возраст ПАК
  -> ВАК по КИП-признакам
```

Нельзя соединять ЛИМС, ПАК и телеметрию по номеру строки.

## Пример логики доверия

```text
ЛИМС свежий
  -> используем ЛИМС как контрольный факт

ЛИМС старый, ПАК свежий
  -> используем ПАК как оперативную оценку
  -> confidence снижается

ЛИМС и ПАК недоступны
  -> используем ВАК
  -> confidence ещё ниже

ВАК противоречит свежему ЛИМС
  -> ВАК не считается контрольным фактом
```

## Как это влияет на агентов

### DQ Checker

Проверяет:

- свежесть ЛИМС;
- свежесть ПАК;
- наличие критичных КИП;
- расхождение ПАК и ЛИМС;
- пригодность источников для рекомендации.

### Quality Agent

Использует:

- ЛИМС как главный target;
- ПАК как оперативный признак или частый target;
- ВАК как baseline и дополнительные признаки;
- КИП как объясняющие признаки.

### Reliability Agent

Использует:

- температуры;
- давления;
- перепады;
- расходы;
- изменения режима;
- исторические модельные диапазоны.

### Scenario Optimizer

Использует:

- только подтверждённые управляемые параметры;
- запреты от Reliability Agent;
- ограничения от DQ Checker;
- прогнозы Quality Agent;
- модельные диапазоны.

## Управляемые и неуправляемые параметры

Не каждый тег является управляющим воздействием.

Нужно разделять:

```text
измеряемые параметры
  -> описывают состояние

управляемые параметры
  -> могут быть изменены в сценарии

ограничения
  -> задают допустимые границы

качество продукта
  -> главный критерий безопасности
```

Если для параметра нет подтверждённого рабочего диапазона, исторический минимум и максимум нельзя называть промышленным пределом. Можно использовать модельный диапазон, но его нужно явно пометить как допущение.

## Короткое резюме

Данные в системе имеют иерархию доверия. ЛИМС является контрольным фактом качества, ПАК даёт оперативную картину, ВАК рассчитывает качество по технологическим признакам, а КИП объясняет состояние процесса. Все источники связываются только по времени, с учётом возраста анализа и задержки отклика качества. Если источники противоречат друг другу, приоритет остаётся за ЛИМС, а уверенность рекомендации снижается.
