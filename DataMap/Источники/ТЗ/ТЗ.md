# ТЗ: требования, связанные с данными

Источник: `ТЗ_нефтекод.docx`, разделы 1-8 и 9 таблиц. Полное текстовое извлечение сохранено в репозитории `tools/datamap/evidence/requirements_extracted.txt`.

## Что должна делать система

Цепочка АВТ -> гидроочистка -> блендинг. Получить состояние, проверить данные, оценить качество и тяжесть режима, сформировать варианты, проверить жёсткие ограничения, сравнить допустимые и объяснить рекомендацию либо отказ. По уточнению команды агенты используют существующие LLM; прогнозы и оценки рассчитывают численные инструменты.

| Требование | Последствие для данных |
| --- | --- |
| ЛИМС > ПАК > ВАК | Контрольный лабораторный факт хранить отдельно от частого оперативного прокси |
| Синхронизация только по времени | У каждой пары Excel своя дата; сохранять возраст анализа |
| Явные единицы | Raw и преобразованные значения/единицы хранить вместе |
| Сера товарного ДТ <= 10 мг/кг | Связь ГО-2 с товарным продуктом пока допущение |
| Сумма долей бленда 100% | Нужны компоненты, массовая/объёмная основа и сценарий |
| Жёсткие ограничения выше экономики | Недопустимый вариант отбрасывать до ранжирования |
| Управляемость обосновать | Датчик не равен уставке, min/max не равен промышленному пределу |
| Разделение по времени | Не обучать на будущем и не размножать лабораторные метки |
| Отказ при недостатке данных | Передавать флаги свежести/качества и причины отказа |
| Python и воспроизводимый запуск | Версии данных, допущения, входы и расчёты должны быть доступны для проверки |

## Минимальная демонстрация

- Нормальный период без лишних управляющих действий.
- Изменение режима или риск ухудшения качества.
- Неполные, устаревшие или аномальные данные.
- Полный цикл взаимодействия агентов с оценками и объяснением.

Дополнительно приветствуются неопределённость прогноза, детекция аномалий, dashboard и сравнение допустимых вариантов. Фиксированных порогов остальных свойств, цен и журнала отказов пакет не содержит.
