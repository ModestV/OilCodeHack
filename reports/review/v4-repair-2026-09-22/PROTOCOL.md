## Обязательные исправления v4 (реализация «v4r»)

1. Строка Stage 1 допускается в обучение/оценку фолда, только если весь
   target-window `(origin+h-30, origin+h+30]` лежит строго до конца фолда
   и до `fit_end`. Число удалённых строк публикуется по fold/horizon/analyser.
2. `quiet_future` проверяет **весь путь** управления в `(origin, origin+h+30]`:
   тихо ⇔ каждое наблюдение отличается от значения на origin меньше допуска
   (T6 1 °C, ln F9 0.02, P13 0.05 МПа), и нет разрыва наблюдений больше 30 мин
   (включая начало и конец окна). Пропуск/разрыв = неизвестно = не тихо.
   Шум внутри допуска — тихо. Постоянное значение — тихо (управляющие теги
   в данных не имеют flatline-флагов; записано как допущение). Скачок,
   попадающий ровно на конец окна, — не тихо; на origin — часть истории.
3. Stage 2 — вложенная схема. Для внешнего фолда k конфигурация
   (вид convex/linear, alpha, конфигурация Stage 1) выбирается только на
   фолдах < k по меткам, опубликованным до начала фолда k. Для первого
   фолда без истории используется заранее зафиксированная конфигурация:
   Stage 1 `all`, alpha 30; Stage 2 `convex`. Квантили остатков — только из
   этих внешних (честных) остатков. Порог тревоги **фиксирован 0.30**
   (как в протоколе v3), не оптимизируется.
4. Support/applicability для внешнего фолда k обучается на метках,
   опубликованных до начала фолда k; финальный support — до `fit_end`.
5. Метки фолда: строка оценивается, только если `available_at` (проба + 240
   мин) лежит до конца фолда. Для каждого семейства признаков — mutation
   test: изменение данных после origin не меняет признаки/прогноз.
6. Свежесть CN/T95 в runtime остаётся 48 ч. Прогноз серы не использует
   CN/T95; анализ 60 сут/7 сут делается только как исследовательская
   чувствительность с явным флагом.
7. Pareto: реализация main (`backend/objectives.py::annotate_pareto`) не
   заменяется.
8. Интеграция только через адаптер с контрактом `forecast_sulfur`; агенты,
   сценарии, партия/запас/транспорт/бленд из main не заменяются. Адаптер
   выключен по умолчанию и включается переменной окружения.

## Кандидаты

1. `naive_previous_lab` — последняя опубликованная проба (≤48 ч).
2. `anchored_q21`, `anchored_pak` — анализатор + медианное смещение по 10
   последним опубликованным парам (bias correction).
3. `v3_ridge` — текущий runtime (`corrected-claude`), его сохранённые
   прогнозы (2024/2025 — прогнозы моделей, обученных до начала года; год
   участвовал в выборе семейства v3, поэтому оценка v3 оптимистична).
4. `v4r` — исправленный двухступенчатый v4.
5. `hgb_fixed` — HistGradientBoosting на тех же входах Stage 2 + support,
   **фиксированные** гиперпараметры (без подбора), та же walk-forward схема,
   те же вложенные квантили. Абляция, не кандидат по умолчанию.
6. Физическая/кинетическая модель — не пересчитывается (единицы и
   катализатор не подтверждены); статус в матрице методов.

## Оценка

- Walk-forward: `fit_end` 2024-01-01, 2025-01-01, 2026-01-01; окно каждой
  модели — `[fit_end, следующий fit_end)`.
- **Годы разработки (решение): 2024 и 2025.** 2026 — ретроспективный аудит,
  уже просмотренный ранее; на выбор не влияет. Слепого holdout в данных нет
  (данные заканчиваются 2026-08-11 и все просматривались); это пишется явно.
- Общая маска: строки, где `forecast_status == ok` у v3 и v4r одновременно
  и цель конечна. Наивные базовые линии оцениваются на той же маске; где
  предыдущая проба недоступна — подставляется локальный уровень (5 проб),
  доля подстановок публикуется. Покрытие каждой модели — отдельная таблица.
- Метрики по кандидату × горизонту × году: n, покрытие, MAE, RMSE, медиана
  |e|, bias; для вероятностных — Brier, Brier skill, AUC; recall/precision/FPR
  при S>10 для точечного прогноза и для P≥0.30; покрытие 80% интервала.
- Парные разности MAE и Brier к v3 и к naive: недельный блочный bootstrap,
  2000 повторов, seed 42, 95% CI.

## Правило решения (фиксировано)

v4r признаётся **лучше v3 на годах разработки**, если на объединённых
2024+2025 общей маски одновременно:

- H0 и H60: верхняя граница 95% CI MAE(v4r − v3) < 0;
- H120 и H180: верхняя граница 95% CI MAE(v4r − v3) < 0.02·MAE(v3)
  (не хуже больше чем на 2%);
- Brier(v4r) ≤ Brier(v3) + 0.005 на каждом горизонте;
- recall при P≥0.30 для S>10 не ниже, чем у v3, на каждом горизонте,
  где есть хотя бы 5 превышений.

Даже при выполнении правила **замена runtime не производится** в этой
работе: нет слепого holdout. Максимальный статус — «кандидат для теневого
режима (shadow) с проспективной проверкой на данных после 2026-08-11».
Если правило не выполнено — статус «исследование», runtime остаётся v3.

## Критерии приёмки инженерной части

- Все тесты main проходят; новые тесты из раздела B handoff проходят.
- Runtime/offline parity адаптера: все 2026 origins × 4 горизонта и
  выборка ≥ 200 origins на каждый из 2024 и 2025; допуск 1e-9 по ln и
  точное совпадение статуса.
- Process chain (партия, запас, транспорт, бленд, присадка) проходит с
  v3 по умолчанию и с включённым адаптером v4r.
