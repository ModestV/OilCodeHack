# Ремонт v4 → v4r и честное сравнение — 22.09.2026

**Статус: исследование. Runtime остаётся v3.** Исправленная двухступенчатая
модель (v4r) не выполнила заранее зафиксированное правило продвижения на
годах разработки 2024–2025. Она доступна только как opt-in теневой вариант
(`OILCODE_FORECAST_MODEL=two-stage-v4r`) с контрактом и процессной цепочкой main.

- Протокол зафиксирован до расчётов: [PROTOCOL.md](PROTOCOL.md) (`d6a4939`,
  поправка `a48a177` до первого расчёта).
- Решение: [AGENT/decisions/2026-09-22-v4r-not-promoted.md](../../../AGENT/decisions/2026-09-22-v4r-not-promoted.md).
- База: `main@bbb6a34`. Источник: `feat/forecast-v4-contour-v2@2397769` (не менялся).
- Слепого holdout нет: все данные до 2026-08-11 уже просматривались.
  2026 — ретроспективный аудит, на выбор не влиял.

## Что исправлено (v4 → v4r)

| # | Ошибка v4 | Исправление | Тест |
|---|---|---|---|
| 1 | Строки Stage 1 ограничивались по origin, target-window `(t+h−30, t+h+30]` заходил за конец фолда | строка входит в фолд/обучение, только если окно кончается до границы; удалённые строки публикуются | `test_target_window_crossing_fold_end_is_not_a_fold_row`, `test_crossing_report_counts_removed_rows` |
| 2 | `quiet_future` сравнивал только концы окна (350→360→350 = «тихо») | проверка всего пути `(t, t+h+30]`: каждое показание в допуске, разрывы > 30 мин и flatline — «не тихо» | 8 тестов `test_quiet_*`, `test_future_path_quiet_log_mode` |
| 3 | Stage 2 выбирал alpha/вид и считал остатки на одном фолде | вложенная схема: конфигурация фолда k выбирается только на фолдах < k (первый — заранее заданная); квантили — только из внешних OOF-прогнозов; порог тревоги фиксирован 0.30 | `test_outer_fold_model_set_does_not_see_outer_labels`, `test_first_fold_uses_preregistered_configuration`, `test_residual_quantiles_come_only_from_outer_predictions` |
| 4 | Support/gate обучался на всём fit-периоде | support фолда — только на метках, опубликованных до начала фолда | тот же `test_outer_fold_model_set_…` |
| 5 | Будущие точки в признаках/отклике | mutation-тесты всех семейств признаков, Stage 1 и всего набора моделей; метки фолда — только опубликованные до конца фолда | `test_*_ignore*_future*`, `test_fit_procedure_ignores_everything_after_cutoff`, `test_fold_rows_require_publication_before_fold_end` |
| 6 | CN 60 сут / T95 7 сут | runtime 48 ч без изменений; прогноз не использует CN/T95; отдельная исследовательская оценка ниже | `test_forecast_ignores_quality_freshness_settings` |

| 8 | Полное слияние теряло партию/запас/транспорт/бленд | адаптер `backend/forecast_two_stage.py` с контрактом v3; агенты/сценарии main не тронуты | `tests/test_two_stage_runtime.py`, acceptance 8/8 |

Число строк, пересекавших конец фолда, совпадает с аудитом `new-branches`
(например, 2025/H180: 7 строк Q21 и 7 ПАК) — [metrics.json](../../modeling/two-stage-v4r/metrics.json).
После исправления «тихих» строк в нормальном режиме: 23% (H60), 10% (H120),
4.7% (H180); вариант `quiet_future` выбирается только для Q21 H60.

## Отклонения от протокола (записаны до интерпретации)

1. **Сохранённые прогнозы v3 за 2024/2025.** Колонка `prediction` — это
   in-sample финальной модели (обучена до 2026). Использована `oof_prediction`
   (модель, обученная на предыдущих годах), как и описано в протоколе. Но
   вероятность `oof_exceedance_probability` построена на квантилях из тех же
   2024–2025, а сохранённый статус — gate финальной модели. Поэтому добавлен
   второй эталон **`v3_refit`**: рецепт v3 (log-ridge на 6 anchored-входах),
   переобученный по тому же вложенному протоколу, что и v4r. Правило решения
   проверено против обоих эталонов.
2. В общую маску добавлен `v3_refit` (и базовые линии); это сужает маску
   на несколько строк и не влияет ни на одну модель избирательно.
3. Для anchored Q21/ПАК, как и для naive, пропуск заменяется локальным
   уровнем; доля подстановок ≤ 3.3% (`level_substituted_fraction`).

**Сравнение со старым аудитом v4 (`2397769`) на тех же 234 строках:** MAE
v4 было 1.081 / 1.149 / 1.320 / 1.403, CI для H60 — [−0.174, −0.046].
После ремонта H0 не изменился (Stage 1 не участвует), **выигрыш на H60
уменьшился (1.149 → 1.194) и перестал быть значимым** — часть преимущества
v4 на H60 давали методологические ошибки. H120/H180 почти без изменений.
Актуальный результат — v4r (эта ветка); цифры `new-branches/audit.json`
для v4 считаются устаревшими.

## Покрытие и отказы

Покрытие на собственной маске ([coverage.csv](coverage.csv)): v4r и v3 refit —
0.94 на 2024+2025 и 0.93 на 2026. У сохранённого v3 на 2024+2025 — 0.97–0.98,

Превышения среди отказов 2024+2025: 10–15 у v4r/v3 refit на горизонт.

## Свежесть CN/T95

Реальный `make_decision` (H180) на 1055 lab-origins 2024–2026, runtime-политика
48 ч не менялась ([freshness_sensitivity.json](freshness_sensitivity.json),
[freshness_sensitivity.csv](freshness_sensitivity.csv), [freshness_rows.csv](freshness_rows.csv)).
Прогноз серы CN/T95 не использует (проверено тестом), поэтому эффект модели
и эффект свежести разделяются.

**Сравнимо только 2026:** артефакт v3 доступен с 2026-01-01 и на 2024–2025
отказывает по построению (`model_not_yet_available_at_origin`), а v4r имеет
walk-forward модели с 2024 г. Покрытие 2024–2025 у v4r (4–5%) поэтому не
является выигрышем над v3.

2026, 253 origin, по возрасту последнего опубликованного цетанового числа:

| возраст CN | origin | рекомендаций 48 ч v3 / v4r | блок только из-за CN/T95 v3 / v4r | верхняя граница при 60 сут/7 сут v3 / v4r |
|---|---:|---|---|---|
| ≤ 2 сут | 11 | 7 / 6 | 0 / 0 | 7 / 6 |
| 2–7 сут | 43 | 0 / 0 | 26 / 25 | 26 / 25 |
| 7–30 сут | 114 | 0 / 0 | 59 / 58 | 59 / 58 |
| 30–60 сут | 65 | 0 / 0 | 48 / 45 | 45 / 43 |
| > 60 сут | 20 | 0 / 0 | 9 / 9 | 0 / 0 |
| **всего** | 253 | **7 / 6** (2.8% / 2.4%) | 142 / 137 | **137 / 132** (54% / 52%) |

- При политике 48 ч смена модели v3 → v4r покрытие не увеличивает (7 → 6).
- Ослабление CN до 60 сут и T95 до 7 сут дало бы рост в ~20 раз у обеих
  моделей: рост покрытия в исходном v4 объясняется политикой свежести, а не
  прогнозом. Цетан свежий (≤ 48 ч) лишь в 4.3% origin 2026; медиана возраста
  CN — 18.9 сут, T95 почти всегда свежий (97%).
- Верхняя граница: после снятия gate последующие проверки не перезапускались.
  Это исследовательская оценка, в runtime не применяется; технологического или
  организационного обоснования для 60 сут не найдено.
- Все origin попали в класс режима `normal`, поэтому разрез «по режиму»
  вырожден; разрез по возрасту T95 — в CSV.

## Ограничения

- Слепого holdout нет. Требование handoff «открыть нетронутый блок один раз»
  выполнить нельзя; следующий честный шаг — проспективная проверка на данных
  после 2026-08-11 с этим же правилом.
- HGB с фиксированными параметрами — абляция без подбора; на H0/H60 он
  близок к лучшим по MAE, но с худшим Brier. В кандидаты не выдвигается.
- Физическая/кинетическая модель не пересчитывалась (единицы, катализатор
  и отказы не подтверждены).
- Коэффициенты отклика на T6/F9/P13 — наблюдательные; причинность и
  промышленная безопасность не заявляются.
- RMSE на H180 ≈ 4.5 у всех моделей — несколько аномальных проб в 2024–2025
  доминируют; поэтому основной критерий — MAE и парные CI.
