# Развитие калиброванного прогноза серы — 21.09.2026

## Результат

Подход Claude исправлен и проверен на историческом воспроизведении. Существенного
подтверждённого роста точности концентрации от усложнения модели не найдено.
Для runtime оставлен **исправленный калиброванный Ridge**, переобученный без
обнаруженного использования будущих данных. Новые модели сохранены как
воспроизводимые эксперименты. Основная ценность этой итерации — корректность
времени, одинаковые расчёты offline/runtime и честное сравнение альтернатив.

Это отдельная ветка `codex/causal-anchored-forecast` от Claude `ddb8e4c`.
Она **не включает** нашу ветку `codex/process-corrections` (`903ae91`), где
реализованы партия, запас, транспорт и конечный бленд. Нельзя заменять ею
весь интеграционный проект: переносить исправления прогноза выборочно.

## Данные и смысл оценки

Импортированный `observations.parquet`:
`9a6d9b644a2b1ddce0da27e816aad31654ea9aaf306f29865bb14503973db37b`.
Цель `lims.ht.2.Mg.Sulfur`: 1462 отдельных неотрицательных лабораторных проб.
Для каждой — момент прогноза за 0/60/120/180 минут до отбора. ЛИМС становится
доступна через 4 часа, телеметрия ограничена моментом прогноза. Пробы 2026
уже просматривались в предыдущих исследованиях: это ретроспективный аудит,
а не новый слепой тест. Признаки и коэффициенты не подбирались по его метрикам
в текущих экспериментах.

Последние 10 опубликованных пар ЛИМС/анализатор за максимум 45 дней задают
медианное смещение анализатора; последние 5 проб — локальный уровень.
Срок последней отдельной пробы 48 часов отсчитывается от отбора.
Калибровочное окно 45 дней и срок отдельной пробы 48 часов имеют разный смысл.
Все эти окна — допущения модели, не гарантии сохранения свойств продукта.

## Исправления, сохранённые в коде

1. Плато не удаляет предыдущие показания задним числом. Значение отбрасывается
   только после того, как длительность плато достигла 60 минут.
2. H0/H1/H2/H3 используют собственные границы применимости. Интерполяция
   требует допустимости двух соседних моделей. Недопустимый nowcast не
   публикуется; недопустимая промежуточная точка блокирует наблюдаемое решение.
3. Управляющие отклики оцениваются только до 2026 года, включая весь будущий
   участок отклика каждого исторического события. Это наблюдательные, а не
   доказанные причинные коэффициенты. Также исправлено выравнивание времени
   анализатора и управляющих тегов при разных индексах.
4. Point/interval/P(превышение) сценария используют один конечный уровень:
   эффект серы сырья нарастает с той же долей отклика. Исправлено и обратное
   решение автоматического воздействия на коротком горизонте.
5. Проверка применимости на OOF-фолдах обучается внутри каждого фолда.
   Остатки для калибровки берутся с допустимых OOF-строк, не с будущими
   границами поддержки. Подбор α/порога и калибровка всё ещё используют
   одни годы; их внутренние метрики нельзя называть независимой валидацией.
6. Цетан не считается актуальным 60 дней: восстановлено прежнее рабочее
   ограничение 48 часов. Это отдельная политика доказательств; её изменение
   не считается улучшением модели.

## Сравнение моделей концентрации

Заранее зафиксированы `PROTOCOL.md` и `CALIBRATION_PROTOCOL.md`.
Проверены 12 вариантов: log-Ridge, Huber в обычных и логарифмических единицах,
неотрицательные смеси с суммой весов 1 и L1-ошибкой, отдельные анализаторы,
последняя проба, локальная медиана. Все оцениваются на одинаковых строках.
Смесь ограничивает влияние каждого источника, но не является физической
моделью гидрообессеривания.

Выбор по 2024; подтверждение по 2025 с минимальным выигрышем MAE 2% и
ограничением роста RMSE 5%. Ни один challenger не прошёл этот критерий.
На H1 convex-log дал 1.171 против 1.182 мг/кг, но выигрыш всего 0.9%;
на H2/H3 лучшие по 2024 смеси ухудшили результат 2025.

Дополнительно проверены 12 сочетаний длины калибровки и локальной медианы.
Победитель 2024 — 10 пар и медиана 3 проб. На 2025 относительный
выигрыш средней MAE по горизонтам 0.65%, ниже порога 2%; оставлены 10/5.
Данные 2026 исключены из этого поиска ещё до построения признаков.

Ретроспективный аудит 2026; по 253 возможных момента прогноза на горизонт:

| Горизонт | Принято | Исправленный Claude, MAE | Новый протокол выбора, MAE |
|---|---:|---:|---:|
| Сейчас | 235 | 1.175 | 1.178 |
| +1 час | 236 | 1.280 | 1.287 |
| +2 часа | 236 | 1.389 | 1.390 |
| +3 часа | 236 | 1.452 | 1.462 |

Единицы MAE — мг/кг. Строки в каждом сравнении совпадают. Новый протокол
выбрал Ridge α=100 на всех горизонтах; он не заменил исправленный incumbent.
Метрики всех вариантов, всех строк и строк с полными шестью признаками,
RMSE и парные bootstrap-интервалы по дням сохранены в `metrics.json`.
Точность по принятым строкам не описывает отброшенные режимы установки.

## Отдельная модель риска

`RISK_PROTOCOL.md`: логистическая регрессия события S>10 с теми же шестью
признаками, четыре C, выбор Brier по 2024, подтверждение по 2025. Сравнения
используют прошлую частоту превышений и остаточную вероятность Ridge,
калиброванную на предыдущем году. Порог тревоги фиксирован 0.30.

Только H1 прошёл условие снижения Brier хотя бы на 2% относительно обоих
сравнений и не худшего AUC в 2025. Brier 0.14078 → 0.13732 (−2.45%).
В 2026 относительно **этого же годового residual-baseline**: 0.12001 →
0.11610 (−3.26%), AUC 0.697 → 0.711 на 236 общих строках.

Это не доказательство превосходства над всеми вариантами Claude: у него
другая калибровка остатков. И это не выигрыш полноты тревог: при пороге .30
классификатор на 2026 обнаруживает 4/34 превышений и даёт 9 ложных тревог;
residual-baseline — 17/34 и 33 ложных. На 2025 полнота тоже ниже.
Классификатор оставлен диагностическим экспериментом, в safety gate не
подключён. Перенос его вероятности на сценарий с изменёнными управлениями
не обоснован. Нужна отдельная постановка стоимости пропуска и ложной тревоги,
после чего порог следует выбирать на прошлом периоде и проверять на новом.

## Ограничения

- H3 остаётся слабым: точечный Ridge не обнаруживает превышения порога,
  остаточная вероятность близка к частотной по Brier. Близкая к среднему
  концентрация не доказывает безопасность режима.
- Номинальные 80%-интервалы исправленного варианта покрывают примерно
  75–77% принятых фактов 2026. Это эмпирические интервалы с дрейфом, не гарантия.
- Отсутствуют независимые вмешательства, подтверждённые лаги, активность
  катализатора, корректные единицы части потоков и все технологические
  ограничения. Усложнять кинетическую формулу с вымышленными параметрами
  нельзя считать физическим обоснованием.
- Ограничения старой ветки Claude по товарной смеси и ВАК сохраняются здесь;
  интеграция с `codex/process-corrections` требует отдельного слияния.
- Main, сервер и пользовательский DataMap этой итерацией не обновлялись.

## Воспроизведение

Python 3.12; зависимости для исследований —
`tools/modeling/requirements-research.txt`, runtime — корневой requirements.txt.
Из корня этой ветки, подставив каталог импортированного dataset:

```powershell
python -X utf8 tools/modeling/sulfur_forecast.py --dataset DATASET --output reports/modeling/causal-anchored/corrected-claude
python -X utf8 tools/modeling/anchored_challengers.py --dataset DATASET
python -X utf8 tools/modeling/calibration_memory.py --dataset DATASET
python -X utf8 tools/modeling/anchored_risk.py --dataset DATASET
python -X utf8 tools/modeling/replay_anchored.py --dataset DATASET
python -m pytest tests tools/modeling/test_sulfur_forecast.py -q
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend test
```

Runtime использует `corrected-claude/model.json`. Верхний `model.json` —
отдельный challenger по замороженному протоколу. `risk-model.json` —
диагностический классификатор, не runtime. Старый каталог `sulfur-forecast`
сохранён как исторический результат Claude и больше не является default.

`runtime-parity.json/csv`: 1012 as-of prefix-проверок для каждого из двух
артефактов; дополнительно прямые вызовы чтения Parquet в контрольных точках.
Проверяются признаки, решение о применимости, прогноз, границы интервала и
вероятность. В replay полные данные никогда не передаются построителю
признаков в качестве доступной на момент прогноза истории.

Проверки кода: 95 Python-тестов (backend и модельные), 11 frontend-тестов;
TypeScript и production build проходят. Визуальный интерфейс не изменялся,
обновлён только TypeScript-контракт допустимости точек прогноза.
