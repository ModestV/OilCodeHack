# Нефтекод

Мониторинг качества дизеля после гидроочистки по загруженной истории КИП, ЛИМС и ПАК, сценарные рекомендации и песочница блендинга. Доступны выбор момента или периода, статистика, сопоставление источников, диагностика данных и 17 ВАК, включая исправленные экспертом формулы.

## Запуск

Требуются Python 3.11–3.13, Node.js 22.12+ и npm. Все данные обрабатываются локально.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
npm --prefix frontend ci
.venv/bin/python scripts/import_demo.py '/путь/к/Нефтекод_2.0'
.venv/bin/python scripts/dev.py
```

Команда импорта необязательна: файлы можно загрузить через интерфейс. Сервер запускается на `http://127.0.0.1:5173`, API — на `http://127.0.0.1:8000`. Если порт занят, скрипт выбирает следующий и печатает точный URL. Остановка обоих процессов — Ctrl+C.

В Windows используйте `python -m venv .venv`, затем `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Путь к исходному комплекту передайте явно. Повторный импорт не перезаписывает существующий набор; для новой копии укажите `--id another-id`.

Проект рассчитан на закрытую технологическую сеть без доступа к внешнему
интернету. Мониторинг, прогноз, сценарии и контур агентов работают локально на
детерминированных правилах и обученных офлайн моделях (numpy/pandas, артефакт
JSON); внешние API и языковые модели не используются. Объяснение для
оператора формируется шаблоном из результатов агентов.

Собранный интерфейс можно обслуживать одним процессом:

```bash
npm --prefix frontend run build
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000`. OpenAPI: `/docs`. Готовый набор не требуется переимпортировать после перезапуска.

## Данные

Принимаются CSV КИП АВТ/24-2000, XLSX ЛИМС и ПАК в структуре хакатона, опционально XLSX со справочником. Можно загрузить часть источников. До 8 файлов и 800 МБ на один набор. Файлы `~$…` и архивы не принимаются: CSV уже распакованы в исходном комплекте.

`storage/<id>/raw` содержит неизменные копии загрузок, `observations.parquet` — нормализованные наблюдения, `manifest.json` — паспорт набора. `storage/` исключён из Git. Альтернативный каталог задаётся переменной `OILCODE_STORAGE`.

Ряды имеют разные часы измерений. КИП: 97 сигналов, 189 217 кадров с шагом 10 минут, 01.01.2023–07.08.2026. ЛИМС: 54 независимых ряда на 6 точках отбора. ПАК серы покрывает 2023–2026 годы; плотность ПАК начинается 05.03.2025. Справочник: [docs/data-dictionary.md](docs/data-dictionary.md).

## Правила расчётов

- Все источники используют один часовой пояс; временная шкала хранится без преобразования. Период — `[начало, конец)`.
- Метка ЛИМС означает время отбора пробы. В историческом кадре результат консервативно становится доступен через 4 часа, поэтому будущие знания оператора не подмешиваются. ПАК показан отдельно как оперативное историческое наблюдение.
- Давность по умолчанию: КИП 10 минут, ПАК 30 минут, ЛИМС 48 часов. Это изменяемые допущения прототипа, а не производственный регламент.
- Порог серы 10 мг/кг — контрольный ориентир из ТЗ. Результат после ГО не является сертификацией товарного топлива после блендинга. В обновлённой схеме также заданы T95 ≤360 °C и цетановое число ≥51. Полная марка/сезон не определены.
- Мониторинг не является заключением по ГОСТ/EN без утверждённой спецификации; экономика не может компенсировать нарушение качества.
- Сера ПАК соответствует `Mg.Sulfur` гидроочистки, точка отбора 2; массовый ppm = 1 мг/кг. Ошибочные единицы ЛИМС исправлены по названиям показателей. Неизвестные единицы КИП не используются для расчёта реального выпуска или затрат.
- Статистики считаются по исходным измерениям отдельно для каждого источника. Лабораторные значения не размножаются переносом вперёд. Стандартное отклонение — генеральное (ddof=0), квантили непрерывные, IQR=P75−P25.
- Доля лабораторных проб выше порога не равна доле времени. Время превышения ПАК — удержание измерения максимум 10 минут до следующей точки, с обрезкой границами периода. Разрывы и подозрительные интервалы не входят в достоверное покрытие.
- Шесть часов абсолютно неизменных показаний частого источника дают подозрение на зависание с момента достижения порога. Это не доказательство неисправности. Высокие значения серы не удаляются как статистические выбросы.
- Конфликтующие дубли, нечисловые и бесконечные значения не используются как достоверные числа. Подозрительные числовые значения сохранены; выбор их исключения явный.
- Укрупнение графиков сохраняет медиану и min/max. Расчёт статистики не зависит от числа точек графика.
- Все 17 ВАК взяты из исправленного файла организаторов `Updates/формулы_ВАК.xlsx`; каждая формула в `backend/resources/registry.json` хранит контрольный пример и воспроизводит его в тестах. Лабораторные входы `LIMS.D15` и `LIMS.95%.T` сопоставлены с точкой 2 гидроочистки как явное допущение. Для вычислений используется ограниченное арифметическое дерево, не выполнение произвольного Python. Точность ВАК на истории — в [reports/verification/agent-backtest/REPORT.md](reports/verification/agent-backtest/REPORT.md): `24-2000:GODT:D15` и `IBP` имеют скромную предсказательную силу, `T95` близок к константе, `AVT6:240-350:EBP` даёт ошибку >60 °C и непригоден; остальные — диагностические.

Сценарная модель использует рабочие соответствия из обновлённого справочника: `T6` (температура на входе Р-202), `F9` (массовый расход сырья) и `P13` (давление на входе Р-202). Модель мультипликативная: `ln(сера) = ln(база без воздействия) + эластичность×ln(сера сырья/база)×доля отклика + Σ коэффициент×изменение×доля отклика тега`. База без воздействия — двухступенчатый прогноз, который уже учитывает сделанные до момента решения изменения режима; изменение кандидата задаётся относительно текущих значений, поэтому уже сделанный ход не считается дважды. Коэффициенты по умолчанию — медианные лагированные отклики поточного анализатора Q21 на ступени одного тега по данным строго до `fit_end` модели, применимой к моменту (события одного разгона объединены; для модели 2026: T6 ≈ −0.029 ln/°C по 1451 событию, F9 ≈ +0.018 ln/% по 207, P13 ≈ −0.23 ln/МПа по 449, лаги 120/60/60 мин; implied gain ступени 1 совпадает по знаку и близок по величине; точные значения, bootstrap-ДИ и лаги — в отчёте модели и в `GET /api/scenario-defaults?at=`). Это наблюдательные оценки: эксперт подтвердил только направление для температуры, поэтому коэффициенты, лаги (0–3 ч) и пределы изменения за шаг (±10 °C, ±10 %, ±0.5 МПа) остаются редактируемыми допущениями, а не установленной причинностью; стандартные ошибки коэффициентов расширяют интервал и P(>10) кандидата пропорционально размеру изменения. Сера сырья задаётся в % масс. (по умолчанию последняя опубликованная проба `lims.ht.1.Mass.Sulfur`).

Песочница имитирует смесь резервуаров по сере, T95 и цетановому числу. Цетаноповышающая присадка ограничена 3%, её тонна имеет индекс стоимости 100 при индексе ДТ 1. Эффективность присадки задаётся модельным параметром, поскольку эксперт не предоставил её характеристику.

Модель прогноза серы описана в [reports/modeling/sulfur-forecast/REPORT.md](reports/modeling/sulfur-forecast/REPORT.md). Это двухступенчатая модель. Ступень 1 (динамика): для каждого поточного анализатора (`Q21`, ПАК) и горизонта 60/120/180 мин ridge на плотной 30-минутной сетке предсказывает изменение ln анализатора по его истории (текущее, 1/6/24 ч) и по изменениям и уровням управляющих тегов `T6`/`F9`/`P13` за 1/3/6 ч — поэтому путь «без воздействия» учитывает уже сделанные операторами изменения режима. Вариант обучения «тихое будущее» (управления не двигаются до целевого момента) описывает процесс без вмешательства и выбирается на фолдах, если не хуже общей модели. Ступень 2 (калибровка): предсказанные значения анализаторов корректируются на медианное смещение «ЛИМС − анализатор» по последним 10 опубликованным пробам и объединяются с локальным уровнем и предыдущей пробой выпуклой комбинацией в ln (веса ≥0, Σ=1) или робастной (Huber) линейной моделью; интервалы и вероятность превышения 10 мг/кг — из out-of-fold остатков. Очистка анализаторов каузальна (плато ≥60 мин и значения вне (0, 100) отбрасываются без взгляда вперёд). Артефакт walk-forward: модели с `fit_end` 2024-01-01, 2025-01-01 и 2026-01-01, каждая обучена и настроена (α, вид ступени 2, порог тревоги, квантили) только на пробах и фолдах до своей даты; runtime берёт последнюю модель с `fit_end ≤ момент прогноза`, поэтому исторический прогноз доступен с 2024-01-01 без будущей информации. При отсутствии свидетельств, режиме вне области обучения (проверяется по каждому горизонту) или нехватке пар для калибровки возвращается `abstain`; при неполных входах ступени 1 используется персистентность анализатора с отдельными квантилями. Предыдущие итерации (Ridge на 292 признаках телеметрии, [reports/modeling/sulfur-first-iteration/REPORT.md](reports/modeling/sulfur-first-iteration/REPORT.md); ridge только по свидетельствам серы без динамики) были не лучше константы на горизонте 180 мин и заменены.

## Архитектура

Момент и период используют разные представления. Сводка сначала сообщает оператору о превышениях и достоверности данных, затем ведёт к нужному тренду или диагностике. В моменте видны точные измерения, их давность, изменение относительно предыдущего измерения и состояние серы; история за 24 часа раскрывается отдельно. В периоде видны агрегаты, покрытие, длительность превышений, распределения и сравнение с предыдущим интервалом. Клик по точке графика открывает момент. Паспорт набора, сгруппированные проблемы, ВАК и настройки свежести находятся в раскрываемых разделах диагностики; ВАК рассчитываются только для момента.

Карточки можно добавлять, убирать и упорядочивать; выбранная статистика и состав сохраняются в браузере. Экспериментальные пороги давности сохраняются для набора. Исследование дизайна с первоисточниками: [docs/design-rationale.md](docs/design-rationale.md).

Диаграммы показывают серу относительно порога, состав времени периода, сравнение медиан и качество сигналов. Поиск доступен в выборе трендов и таблице статистики. Обоснование изменений: [docs/visualization-improvements.md](docs/visualization-improvements.md). Для запуска тестов интерфейса требуется Node.js 22.12+.

`backend/ingest.py` импортирует источники в Parquet. `backend/analytics.py` выполняет запросы DuckDB и расчёты. `backend/formulas.py` вычисляет ВАК. FastAPI в `backend/app.py` предоставляет единый API и импорт в фоновой задаче. React/Vite в `frontend/` отображает API и сохраняет настройки вида в браузере.

Визуальный ориентир: [docs/design/monitoring-concept.png](docs/design/monitoring-concept.png). Концепт получен встроенным Image Gen по структуре мониторинга, затем реализуется обычными компонентами; данные на изображении не являются источником значений приложения. Исходные схемы АВТ доступны в технологическом разделе. Контракты: [docs/contracts.md](docs/contracts.md).

Прототип предназначен для локальной демонстрации. Сценарный расчёт не является промышленным оптимизатором или инструкцией оператору. Авторизация и общий многопользовательский контур в эту версию не входят. Обучение и временная валидация исследовательской модели воспроизводимы; промышленное качество этим не подтверждается.

## Прогноз, ограничения и выбор

`GET /api/datasets/{id}/forecast?at=...&horizon_minutes=180` трактует `at` как момент выпуска прогноза; горизонт 0–180 мин. Анализаторы и телеметрия берутся не позже `at`, предыдущая проба только при `sample_time+240min<=at`. Ответ содержит `nowcast` (сера сейчас), точечный прогноз с 80 % интервалом, `exceedance_probability`, `alarm_above_10`, статус и причины по каждому горизонту (`horizons[]`), результат ступени 1 (`stage1`: предсказанные значения анализаторов, статус `ok`/`fallback_persistence`), уже сделанные изменения управлений (`in_flight_controls`) и применённую walk-forward модель (`model.fit_end`). Признаки обучения и сервиса используют общий код (`tools/modeling/sulfur_features.py`); паритет offline/runtime (статус, причины отказа, прогноз, интервал, P(>10), путь ступени 1) проверяется по каждому горизонту и каждой walk-forward модели. Область применимости обучена только на train и проверяется по горизонтам. Суточная лабораторная проба содержит быструю составляющую и шум анализа (автокорреляция соседних проб 0.0–0.5), поэтому на уровне ЛИМС ошибка ограничена снизу ~1 мг/кг; ступень 1 даёт основной выигрыш на уровне анализатора (см. отчёт: MAE на +180 мин ≈1.06 против ≈1.4 у персистентности), а на уровне ЛИМС — умеренный; актуальные walk-forward метрики по годам и горизонтам — в отчёте модели.

`POST /api/datasets/{id}/decision` выполняет Quality → Reliability → Optimization → Orchestrator; обмен данными между ролями показан в `trace[].consumes/produces`.

- **Агент качества** берёт за базу nowcast анализатора (последняя проба ЛИМС сохраняется отдельным свидетельством), формирует `problem` — требуется ли действие: прогноз без воздействия на горизонте выше редактируемой цели (по умолчанию 9 мг/кг — запас по рекомендации эксперта) или P(>10) выше допустимой (по умолчанию 30 %). Тревога прогноза (порог по F1 на фолдах) — предупреждение, не сама по себе триггер.
- **Агент надёжности** проверяет свежесть/флаги/доступность управляющих тегов и применимость прогноза; считает индекс риска режима `risk` = max(тяжесть, аномалия) с факторами: тяжесть — положение T6/P13/F9 между медианой и верхним краем обучающего режима применимой модели (1 = край, за которым прогноз сам отказывает; классы normal <0.5 ≤ elevated <0.8 ≤ high), аномалия — робастное расстояние Махаланобиса (MinCovDet) баланса реакторного блока (ΔT Р-202, ΔT квенча, ΔP Р-202, квенч/сырьё, ВСГ/сырьё, P13) до обучающего режима (классы по квантилям 95/99 % train). Возвращает **ограничения для оптимизатора** (`constraints`: диапазон train-support, шаговые пределы; при `elevated` шаги вверх T6/P13 ×0.5, при `high` — заблокированы; устаревший/недостоверный тег — заблокирован) и **уверенность** `confidence` — документированный индекс качества входных данных (возраст пробы, пары калибровки, свежесть анализаторов, доля импутации, статус прогноза и ступени 1; произведение факторов, классы high ≥0.75 / medium ≥0.5 / low), не вероятность.
- **Агент оптимизации** оценивает сетку ≈36 кандидатов (удержание; шаги T6 ±1…+10 °C, P13 −0.2…+0.5 МПа, F9 −10…+5 %; пары T6×P13, T6×F9, P13×F9; решение солвера `automatic`; вариант пользователя `requested`) сценарной моделью. Для каждого проверяются сера ≤10, редактируемая цель, P(>10) ≤ допустимой, известные T95/цетан (медленные показатели с окнами 7 и 60 дней; их отклик не моделируется), смесь, край обучающего режима и ограничения агента надёжности. Среди допустимых строится фронт Парето по (P(>10), потеря выпуска, энергия, риск, масштаб изменения); в стабильный период (проблемы нет, hold допустим) выбирается удержание без лишних действий, иначе — минимум взвешенных потерь на фронте; до трёх других членов фронта возвращаются как альтернативы.
- **Оркестратор** разрешает конфликты ролей (качество требует снижения серы, но все подходящие изменения заблокированы надёжностью → отказ с указанием конфликта; низкая уверенность при недопустимом удержании → отказ; эффект выбранного изменения неотличим от нуля с учётом ДИ → предупреждение), проверяет согласованность (общая база у агентов, hold = прогноз без воздействия, знаки эффектов, единый момент решения, отсутствие утечки) и формирует объяснение по блокам ТЗ: состояние → проблема → действие (тег: текущее → рекомендуемое) → ожидаемый эффект → ограничения → уверенность → почему лучше альтернатив. Отказ сохраняет кандидатов и причины, но не выдаёт рекомендацию.

Выпуск = `1+delta_F9_pct/100` при условии постоянного выхода продукта. Энергетический индекс = `1+0.10*delta_T/10+0.05*delta_P/2+0.10*delta_F9_pct/10`; текущий режим равен 1, денежных единиц нет. Среди допустимых вариантов минимизируется `0.5*(1-выпуск)/0.10 + 0.25*(энергия-1)/0.25 + 0.25*риск + 0.15*масштаб_изменения + 0.5*P(>10)/P_max + 0.25*max(0, ln(цель/сера))/ln(1.25)`. Член с P(>10) — прокси ожидаемой стоимости некондиции (по организаторам она в 50–100 раз дороже запаса по качеству); последний член штрафует избыточное снижение серы ниже цели (лишние энергозатраты и износ катализатора без выигрыша по качеству). Веса — явные предпочтения эксперимента. Индексы не могут компенсировать нарушенные ограничения. Действие `review_controls` требует рассмотрения человеком.
