# Решение 2026-09-22: исправленный v4 (v4r) не заменяет runtime v3

**Статус:** принято по заранее зафиксированному правилу
(`reports/review/v4-repair-2026-09-22/PROTOCOL.md`, коммиты `d6a4939`, `a48a177`).

## Контекст

Кандидат `feat/forecast-v4-contour-v2@2397769` (двухступенчатая модель серы)
имел методологические ошибки: target-window пересекал конец фолда,
`quiet_future` проверял только концы окна, Stage 2 выбирал alpha и считал
остатки на одном фолде, support обучался на всём fit-периоде, CN/T95
допускались до 60 сут/7 сут. Все ошибки исправлены в v4r и закрыты тестами.

## Результат

На годах разработки 2024+2025 (общая маска, 748–754 проб на горизонт)
правило продвижения **не выполнено** ни против сохранённых прогнозов v3,
ни против v3, переобученного по тому же вложенному протоколу:

- H0 и H60: разность MAE v4r−v3 не отличается от нуля (95% CI включает 0);
- H120: v4r лучше по MAE (CI < 0), но recall при P≥0.30 ниже;
- H180: не хуже v3 и лучше переобученного v3 по MAE и Brier.

2026 — ретроспективный аудит, уже просмотренный ранее; слепого holdout нет.

## Решение

1. Runtime по умолчанию — v3 (`reports/modeling/causal-anchored/corrected-claude/model.json`), без изменений.
2. v4r доступен только через `OILCODE_FORECAST_MODEL=two-stage-v4r` как
   теневой (shadow) вариант с тем же контрактом и процессной цепочкой main.
3. Свежесть CN/T95 в runtime остаётся 48 ч. Ослабление до 60 сут/7 сут
   не принимается: это изменение политики доказательств, а не модели.
4. Причинная интерпретация и промышленная безопасность не заявляются.

## Условие пересмотра

Проспективная проверка на данных после 2026-08-11 с тем же правилом,
зафиксированным до получения данных; отдельно — целевая проверка H120/H180,
где v4r показал преимущество по MAE на 2024 г., но не на 2025 г.
