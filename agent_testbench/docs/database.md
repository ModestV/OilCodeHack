# Тестовые базы данных

Документ описывает тестовые данные, которые агенты будут получать через оркестратор или напрямую при модульных проверках.

## Основа

Тестовые базы собраны из исходных файлов хакатона:

- `data/avt_tags.csv` - телеметрия АВТ.
- `data/242000_tags.csv` - телеметрия установки 24-2000.
- `ЛИМСы 01.01.2023 - н.в_ (2).xlsx` - лабораторные анализы.
- `Выгрузка ПАК 01.01.2023 - н.в_.xlsx` - поточные анализаторы.
- `Теги_хакатон.xlsx` - справочник ЛА, ВАК, ПАК и КИП.

Исходные файлы не редактируются. В тестовые базы попадает небольшой срез данных и несколько контролируемых ситуаций для проверки агентов. Снапшоты `ProcessState` выбраны внутри диапазона тестовой телеметрии, чтобы агенты анализировали разные режимы, а не один и тот же последний доступный срез.

## Файлы

### `databases/oilcode_agent_test.db`

SQLite-база для оркестратора и интеграционных тестов.

Таблицы:

- `avt_telemetry`
- `unit_242000_telemetry`
- `lims_measurements`
- `pak_measurements`
- `tag_catalog`
- `vak_formulas`
- `agent_test_cases`
- `process_state_snapshots`

### `databases/csv/avt_telemetry.csv`

Малый срез телеметрии АВТ.

Содержит:

- `date`;
- технологические КИП-теги АВТ;
- `test_case` для строк, где есть тестовое условие.

Примеры тестовых условий:

- `missing_avt_flow` - пропуск в расходе `F30`;
- `temperature_jump` - скачок температуры `T66`.

### `databases/csv/unit_242000_telemetry.csv`

Малый срез телеметрии 24-2000.

Содержит:

- `date`;
- температуры, давления, расходы и другие КИП-теги;
- `test_case`.

Примеры тестовых условий:

- `high_reactor_temperature` - повышенная `T5`;
- `missing_feed_flow` - пропуск `F26`;
- `flatline_signal` - серия одинаковых значений `F9`.

### `databases/csv/lims_measurements.csv`

ЛИМС в длинном формате.

Поля:

- `timestamp`;
- `source`;
- `sampling_point`;
- `analyte`;
- `value`;
- `unit`.

Эта таблица используется как контрольный источник качества. Соединять её с телеметрией можно только по времени: берётся последнее измерение не позже времени `ProcessState`.

### `databases/csv/pak_measurements.csv`

ПАК в длинном формате.

Поля:

- `timestamp`;
- `source`;
- `tag`;
- `value`;
- `unit`.

ПАК используется как оперативный источник качества ниже ЛИМС по приоритету.

### `databases/csv/tag_catalog.csv`

Справочник тестовых тегов.

Поля:

- `area`;
- `tag`;
- `description`;
- `is_control_candidate`;
- `is_critical_for_tests`.

`is_control_candidate` не означает промышленно подтверждённую ручку управления. Это только тестовая пометка для сценарного агента.

### `databases/csv/vak_formulas.csv`

Формулы ВАК из справочника хакатона.

Поля:

- `unit`;
- `indicator`;
- `formula`.

На текущем этапе формулы сохраняются как текст. Исполнение формул должно появиться в Quality Agent или отдельном модуле ВАК.

### `databases/csv/agent_test_cases.csv`

Набор тест-кейсов для агентов.

Поля:

- `case_id`;
- `target_agent`;
- `input_table`;
- `condition`;
- `expected_behavior`.

### `databases/json/process_state_snapshots.jsonl`

Готовые входные состояния для агентов.

Каждая строка - один JSON-объект `ProcessState`. Сейчас формируются 4 снапшота:

- `PS-001` - стартовый режим;
- `PS-002` - режим с повышенной `T5`;
- `PS-003` - режим с пропуском `F26`;
- `PS-004` - режим с flatline-окном по `F9`.

```json
{
  "snapshot_id": "PS-001",
  "timestamp": "2023-01-01T00:00:00",
  "avt_telemetry": {},
  "unit_242000_telemetry": {},
  "latest_lims": {},
  "latest_pak": {},
  "features": {},
  "agent_results": {}
}
```

## Связь источников

Данные связываются только по времени:

```text
выбранный момент t
-> телеметрия АВТ на t или последний доступный срез до t
-> телеметрия 24-2000 на t или последний доступный срез до t
-> последний ЛИМС до t
-> последний ПАК до t
-> возраст ЛИМС и ПАК
-> признаки для агентов
```

Нельзя соединять ЛИМС, ПАК и телеметрию по номеру строки.
